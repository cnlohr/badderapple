Exponential-Golomb Encoding
  • Use fewer bits for smaller numbers.
  • Use more bits for bigger numbers.
  • Easy to encode/decode.
  • No need to store a table!
  • Extensively used in H.264 and H.265

int SpeedtropyEmbeddedRead( uint8_t prob )
{
	while( range <= (0x10000) )
	{
		uint8_t data = *(bitstream++);
		range <<= 8;
		value = (value << 8) | data;
	}

	uint32_t split = (range>>8) * prob;
	int bit = value >= split;

	if( !bit )
		range = split;
	else
	{
		value -= split;
		range -= split;
	}
	// 8 asm instructions in fast-path, 18 in slow-path.
	return bit;
}

VPX or "Binary Range Coding"
  • b = a bit (0 or 1)
  • prob = probability of a 0.
    • integer, 0..255 out of 256
  • When encoding: vpx_write(w, b, prob);
  • When decoding: b = vpx_read(w, prob);
  • github.com/cnlohr/vpxcoding
  • codeberg.org/cnlohr/speedtropy
  • Can be arbitrary.
  • Probabilities can change per-read.
  • VPX is a "special" case of range coding.
    • VPX from google's VP8, VP9 video codecs.

void EmitEdge( uint16_t tgprev, uint16_t tg, uint16_t tgnext )
{
    // pixel data is stoblue 8-pixels-at-a-time. The MSB for each pixel is
    // the top byte, and the LSB for each pixel is the bottom byte.

    uint16_t A = tgprev >> 8;
    uint16_t B = tgprev;      // implied & 0xff
    uint16_t C = tgnext >> 8;
    uint16_t D = tgnext;      // implied & 0xff
    uint16_t E = tg >> 8;
    uint16_t F = tg;          // implied & 0xff

    int tghi = (D&E)|(B&E)|(B&C&F)|(A&D&F); // 8 bits worth of MSBs
    int tglo = E|C|A|(D&F)|(B&F)|(B&D);     // 8 bits worth of LSBs

    PMEmit( (tghi << 8) | tglo ); // Write to intermediate framebuffer.
}
